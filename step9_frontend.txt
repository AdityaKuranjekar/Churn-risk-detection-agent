===============================================================================
STEP 9 — FRONTEND SPA  (frontend/index.html)
Churn Risk Agent  ·  detailed end-to-end implementation plan
Aesthetic north star: Vitally / Stripe Dashboard / Linear — calm, dense,
credible internal tool. NOT the generic "AI" look.
===============================================================================

GOAL
----
One self-contained file: frontend/index.html  (+ optional app.js / styles.css
if the agent prefers 3 files — served as static by app/main.py from /).
No build step, no framework. Vanilla JS + fetch. Tailwind via CDN ONLY as a
utility layer with a CUSTOM theme config (see PART B) so it does not read as
default-Tailwind. All product color/typography comes from our tokens.

Two screens, hash-routed:
  #/                     Dashboard  — account table, sorted by risk
  #/customer/{id}        Customer 360 — signals, dual score, analyze/approve

Design pillars (this is what wins the ranking):
  1. PROFESSIONAL: neutral palette, one accent, semantic risk colors only,
     hairline borders over shadows, tabular numbers, no gradients/glassmorphism.
  2. EXPLAINABLE: every number has a "why" — contributor bars, tooltips,
     "two methods" panel, playbook citation shown inline, ML drivers listed.
  3. USER-FRIENDLY: obvious primary action per screen, keyboard shortcuts,
     loading skeletons, empty/error states, nothing blocks on a slow LLM.


-------------------------------------------------------------------------------
PART A — HARD "DO NOT" LIST  (kills the AI-generated look)
-------------------------------------------------------------------------------
  - NO gradient backgrounds, NO backdrop-blur / glass, NO neon glow shadows.
  - NO purple/violet accent. NO 3-color buttons.
  - NO giant radial gauge. NO emoji in headings or buttons.
  - NO huge border-radius (max 8px on cards, 6px on controls, 999px only on
    pill badges).
  - NO more than ONE subtle shadow token, used sparingly.
  - NO center-aligned body text, NO hero section, NO marketing copy.
  - Numbers ALWAYS right-aligned in tables and use tabular-nums.

PART D — SCREEN 1: DASHBOARD  (#/)
-------------------------------------------------------------------------------
Data: GET /api/customers?demo_only=true  -> list[DashboardRow]

D1. Header row of the screen:
  H1 "Accounts" (--fs-20, 600) + count "· 40 accounts".
  Right side: segmented control [ All | At risk | P0 only ] (client-side
  filter). Default "All". A "Sort: Churn risk ▾" menu
  (Churn risk / Health / ARR / Renewal date). Default Churn risk desc.

D2. Summary strip (4 stat tiles, 1 row, thin, border, no shadow):
  - "At risk" = count band in (critical, at_risk)     value in --crit
  - "P0 escalations" = count escalate==true            value in --crit
  - "Avg health" = mean health_score                    value in --text
  - "ARR at risk" = sum(arr where band in crit/at_risk) value in --text
  Each tile: label --fs-12 --text-3 uppercase tracking-wide; number --fs-24
  600 tabular. Border --border, radius 8, padding 16. Hover: none.

D3. Table (the centerpiece). Columns:
  | Account        | Plan | Churn risk        | Health          | Priority | Top signal              | Renewal    |
  - Account: name (600) + tiny id "#3767" (--text-3 --fs-12) below.
  - Plan: pill (Basic/Standard/Premium), neutral style, --fs-12.
  - Churn risk: NUMBER "99%" tabular, right-aligned + a 56px mini bar under
      it (bar fill color = band color, track --surface-2). Sort key.
  - Health: NUMBER "/100" + 56px bar (fill = band color inverted sense: high
      health = green). Tooltip on hover: top 2 contributor labels.
  - Priority: pill P0/P1/P2/P3 with priority color. P0 pill has a small dot.
  - Top signal: single most-negative contributor label + its detail truncated
      (title attr = full detail). e.g. "Recent inactivity · 60d since login".
  - Renewal: relative "in 18d" (--crit if <=30, --high if <=60) or date.
  Row: 52px height, border-bottom --border, hover bg --surface-2, cursor
  pointer -> navigate #/customer/{id}. Focusable (tabindex=0, Enter = open).
  Sticky thead, bg --surface-2, --fs-12 --text-2 600 uppercase.
  Right-align all numeric columns. NO zebra (hairlines are enough).

D4. States:
  - Loading: 8 skeleton rows (shimmer via CSS @keyframes on a --surface-2
      block, subtle, 1.4s). Stat tiles show "—".
  - Error (fetch fails): inline banner --crit-bg, "Couldn't load accounts.
      Retry" button. Console.error the detail.
  - Empty (0 rows): centered --text-3 "No accounts match this filter."

D5. Row click -> push hash #/customer/{id}; keep scroll position on back.

E0. Breadcrumb: "← Accounts" link (back to #/). Then, on the same line,

E2. DUAL SCORE PANEL ("two methods, side by side" — the money shot):

     else: --high-bg row "Rule-based and ML risk differ by
        {gap}. Review signals below." (this candor reads as mature.)

E3. CONTRIBUTOR BREAKDOWN (explainability core):
  Title "Why — health score drivers".
  For each contributor (already sorted most-negative first) render a row:
     [label]                       [detail, --text-3 --fs-12]      [-18.0]
     |------ diverging bar --------|
  Diverging bar: center line at 0; negative impact draws LEFT in --crit,
  positive (from positives[]) draws RIGHT in --ok. Bar max width scales to
  the largest |impact| in the set. Show numeric impact right-aligned tabular.
  Include positives[] at the bottom in green ("Long tenure +3").
  Each row has title= full detail for hover. Keep to <= 8 rows.

E4. USAGE TREND:
  Small card. Header "Usage — last 30 days" + the trend figure
  "▼ 61%" (--crit if <= -20%, --high if <0, --ok if >0) from
  signals.usage_trend_pct.
  Inline SVG sparkline from usage_series[].active_minutes:
     ~ width 100%, height 48, single 1.5px stroke in --accent, faint area
     fill (--accent at 8% alpha), last point a 3px dot. No axes, no grid.
     Tooltip on hover: date + minutes (optional; skip if time-tight).
  Under it: "Logins (30d): {logins_last_30} · Active days: {active_days_30}".

E5. FEEDBACK:
  Card "Recent feedback ({n})". List each feedback_list item:
    channel pill (support/nps/review, neutral) · date --text-3 ·
    sentiment chip: color by sign (--crit <0, --ok >0, --neutral ~0),
    label e.g. "−0.70".
    Then the text (--fs-13). is_complaint -> small "Complaint" tag --crit.
  Empty -> "No feedback on record."

E6. ANALYSIS CARD (right column — the action surface):
  Two visual states:

  (a) NO analysis yet (last_analysis == null):
     Card with a short explainer "Run the agent to get a grounded retention
     recommendation for this account." + big primary button
     "Analyze account" (--accent bg, white, 40px, radius 6).
     Caption under button: "Runs ML scoring, retrieves the matching playbook,
     and drafts outreach. ~3-6s."

  (b) HAS analysis (fresh or after Analyze):
     Header: "Recommendation" + priority pill (P0..P3, colored) +
        if escalate: a --crit-bg strip "P0 — escalate now" with a small
        alert glyph (inline SVG, not emoji).
     "Generated by" caption: map generated_by ->
        gemini:*  -> "AI (Gemini) · grounded in playbook + signals"
        fallback  -> "Template (LLM unavailable)"
        low_risk_shortcut -> "Rule-based · low risk, LLM skipped"
     SUMMARY: the summary text (--fs-14). If it contains "per playbook" /
        "Per playbook", render the playbook title as a subtle inline
        chip/link that scrolls to the playbook box (E7).
     TOP REASONS: bulleted list (custom dash bullet, --text-2), max 3.
     RECOMMENDED ACTION: label in 600 + the elaborated text under it.
     DRAFT MESSAGE: a bordered <textarea> (min 8 rows, --fs-13, mono-ish
        line-height), prefilled with draft_message, editable.
        Above it a row: "Draft outreach" label + char count.
     APPROVE BAR (sticky bottom of card):
        [ Approve ]  primary (--ok bg white text)
        [ Save edit ] secondary (border) — enabled only if textarea changed
        [ Dismiss ]  ghost (--text-3), confirm via a small inline
                     "Dismiss this recommendation? [Yes] [No]"
        Each -> POST /api/customers/{id}/approve
           Approve  -> {status:"approved", message:<textarea current>}
           Save edit-> {status:"edited",   message:<textarea current>}
           Dismiss  -> {status:"dismissed", message:""}
        On success: toast "Saved" + update a status line
           "Status: approved · just now" and disable the bar (re-enable on
           further edit). Re-fetch detail to sync.
     RE-ANALYZE: a small ghost link top-right "Re-run" -> same POST analyze,
        replaces card content (confirm if current status != new).

E7. PLAYBOOK BOX (below analysis card or in left col bottom):
  "Retrieved playbook" — playbook.title (600) + method chip
  ("semantic match 0.73" if method=="embedding" else "keyword match") +
  low_confidence -> --high tag "low confidence".
  Then playbook.text in a --surface panel, --fs-13, italic-free.
  Caption: "Selected by cosine similarity over the retention playbook corpus."

E8. States:
  - detail loading: skeleton for identity + score + a spinner in analysis card
  - Analyze in-flight: button -> disabled, label "Analyzing…", a determinate-
    looking 3-step ticker under it:
       "Scoring signals" -> "Retrieving playbook" -> "Drafting outreach"
       (advance on a timer ~1.2s each; purely cosmetic but reads well and
        matches the real pipeline stages). Cap at step 3 until response.
  - Analyze error: inline --crit-bg "Analysis failed. Retry." (should be rare
    — orchestrator degrades server-side; this is for network only).
  - approve error: toast --crit "Couldn't save. Retry."

PART F — JS ARCHITECTURE  (keep it small, ~400-600 lines)
-------------------------------------------------------------------------------
No framework. Structure:

  const API = (location.origin) ;           // same-origin; endpoints /api/*
  async function api(path, opts) {
     const r = await fetch(API + path, {headers:{'Content-Type':'application/json',
        ...authHeader()}, ...opts});
     if (!r.ok) throw new ApiError(r.status, await r.text());
     return r.json();
  }
  function authHeader(){ /* if window.__BASIC__ set -> Authorization: Basic ..
     ; for now returns {} because AUTH_DISABLED=1 */ }

  // tiny render helpers
  el(tag, attrs, ...children)                // hyperscript-ish
  fmtPct(x) fmtMoney(x) fmtDays(n) relDate(iso) bandColor(b) prioColor(p)

  // router
  window.addEventListener('hashchange', route);
  function route(){
     const h = location.hash || '#/';
     if (h.startsWith('#/customer/')) renderCustomer(+h.split('/')[2]);
     else renderDashboard();
  }

  // views
  renderDashboard():  api('/api/customers?demo_only=true') -> build table,
     wire filters/sort client-side, cache in memory for back-nav.
  renderCustomer(id): api(`/api/customers/${id}`) -> build 360; wire
     Analyze -> api(`/api/customers/${id}/analyze`, {method:'POST', body:'{}'})
     approve -> api(`/api/customers/${id}/approve`, {method:'POST',
                 body: JSON.stringify({status, message})}).

  // components
  sparkline(points, opts) -> returns <svg> string/node
  divergingBar(value, maxAbs) -> node
  scoreBar(pct, color) -> node
  pill(text, color) toast(msg, kind) skeleton(n)

State: module-scoped objects  { dashboard: rows|null, current: detail|null }.
No global framework state; re-render the whole view on nav (cheap at this
scale). Keep the textarea's edited value in a local var so re-render of
sibling parts doesn't clobber it (or just don't re-render the analysis card
while editing).

Accessibility:
  - table rows: role="button" tabindex="0", Enter/Space activate.
  - all interactive controls are real <button>/<a>, focus-visible outline
    (2px --accent).
  - color is never the ONLY signal: pills have text (P0, "Critical"),
    bars have numbers.
  - textarea has a <label>. Toasts use aria-live="polite".
  - prefers-reduced-motion -> disable shimmer + the analyze ticker animation.

Keyboard shortcuts (nice for the demo, cheap):
  "/" focus filter (dashboard) ; "j/k" move row selection ; Enter open ;
  "a" on 360 = Analyze ; "esc" = back to dashboard ; "?" = shortcuts modal.

PART G — SERVING / WIRING
-------------------------------------------------------------------------------
  - File lives at frontend/index.html (app/main.py already mounts
    StaticFiles(directory="frontend", html=True) at "/").
  - Same-origin fetch: no CORS needed in prod. In dev if you open the file
    directly (file://) it WON'T work — always load via
    http://localhost:8000/ so /api/* is same-origin.
  - Tailwind CDN <script src="https://cdn.tailwindcss.com"></script> then
    tailwind.config = { theme: { extend: { colors: {...our tokens...},
    fontFamily: { sans: [...] }, borderRadius:{DEFAULT:'8px'} } } }.
    NOTE: CDN Tailwind is fine for a hackathon/demo. If the Render CSP or
    reviewers dislike CDN, inline a ~4kb hand-written utility CSS instead —
    the token block in PART B covers 90% of it. Decide early; don't mix.
  - Favicon: a 1-color SVG data-URI (simple shield or spark). No external.
  - Put a <noscript> line: "This dashboard requires JavaScript."
