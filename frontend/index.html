How the Churn Risk Agent works

Ingest
~10,000 accounts: usage, billing, support, engagement, feedback
Features
40+ signals per account: tenure, usage trend, payment failures, sentiment, and support tickets
ML model
XGBoost predicts probability of churn · ROC-AUC 0.88
Health score
Transparent 0–100 score from weighted, explainable factors
RAG
Semantic match against 10 retention playbooks
LLM
Gemini drafts grounded, personalized outreach
Two independent methods score every account — a rule-based health score you can audit, and an ML churn probability. The LLM only elaborates; it never changes the recommended action or priority.
Health Score (Rules)
Healthy (70–100) · Watch (50–69) · At Risk (30–49) · Critical (0–29)
Churn Model (ML)
≥ 70% triggers P0 workflow
40–69% triggers P1 workflow
≤ 39% ignores ML workflow (unless health is critical)
Routing Priority
P0 (Critical) — Needs immediate CSM intervention. Triggered by high ML churn probability + drop in usage.
P1 (High) — Standard risk. Triggered by support tickets, sentiment, or moderate ML score.
P2 (Medium) — Low risk, requires light touch.
P3 (Low) — Healthy accounts.
