GOAL
----
A thin, import-once inference layer around the trained XGBoost model so the
orchestrator (Step 7) can turn a customer DB row into a churn probability with
a single call, and never drift from how the model was trained.

  load churn_model.pkl / feature_columns.pkl / preprocess.pkl ONCE at import
  predict(feature_dict) -> float in [0,1]
  build_feature_dict(customer_row) -> dict   (DB row -> model input)
  predict_from_customer(customer_row) -> {"churn_probability", "band",
                                          "top_features", "model_version"}

HARD RULE
  Feature derivation lives in EXACTLY ONE place: ml/features.py.
  Both ml/train_model.py (Step 2) and this file import it. If you find any
  derived-feature math duplicated here, delete it and call features.py.

B0. PATHS / LOAD-ONCE (module level, runs at first import)
    import joblib, json, os, numpy as np, pandas as pd
    from pathlib import Path
    from ml.features import derive_features            # single source of truth

    ML_DIR = Path(os.getenv("ML_DIR", "ml"))
    MODEL_PATH   = ML_DIR / "churn_model.pkl"
    COLS_PATH    = ML_DIR / "feature_columns.pkl"
    PRE_PATH     = ML_DIR / "preprocess.pkl"
    CARD_PATH    = ML_DIR / "model_card.json"

    class ModelNotLoaded(RuntimeError): ...

    def _load():
        if not MODEL_PATH.exists():
            raise ModelNotLoaded(
                f"{MODEL_PATH} missing - run `py ml/train_model.py` first")
        model = joblib.load(MODEL_PATH)
        cols  = joblib.load(COLS_PATH)                 # ordered list[str]
        pre   = joblib.load(PRE_PATH)                  # {"medians":{...}, ...}
        card  = json.loads(CARD_PATH.read_text()) if CARD_PATH.exists() else {}
        return model, cols, pre, card

    _MODEL, _COLS, _PRE, _CARD = _load()
    _MEDIANS  = _PRE.get("medians", {})
    _THRESH   = float(_CARD.get("threshold_used", os.getenv("CHURN_THRESHOLD", 0.5)))
    _VERSION  = _CARD.get("trained_at", "unknown")

    NOTE: import-time load means a missing pkl crashes app startup with a clear
    message. That's desired (fail fast). Step 8 main.py can catch ModelNotLoaded
    in its lifespan and log a friendly hint.

B1. build_feature_dict(customer_row: dict | Mapping) -> dict
    Purpose: normalize a raw `customers` table row into the flat input
    derive_features() expects. Handles column-name differences and types.

        def build_feature_dict(row) -> dict:
            g = (lambda k, d=None: row.get(k, d)) if hasattr(row, "get") \
                else (lambda k, d=None: getattr(row, k, d))
            fd = {
              "tenure_days":      _num(g("tenure_days"), 0),
              "monthly_charges":  _num(g("monthly_charges"), 0.0),
              "arr":              _num(g("arr"), _num(g("monthly_charges"),0)*12),
              "plan_tier_ord":    int(_num(g("plan_tier_ord"),
                                     {"Basic":0,"Standard":1,"Premium":2}
                                     .get(g("plan_tier"), 1))),
              "num_devices":      int(_num(g("num_devices"), 1)),
              "age":              g("age"),                # may be None
              "payment_failures": int(_num(g("payment_failures"), 0)),
              "support_contacts": int(_num(g("support_contacts"), 0)),
              "engagement_score": _num(g("engagement_score"), None),
              "last_login_days":  int(_num(g("last_login_days"), 0)),
              "usage_level":      _num(g("usage_level"), 0.0),
            }
            return fd
        # _num(v, default): float(v) if v not None/NaN/'' else default

    This mirrors BASE_COLS. If Step 2 used a different base set, MATCH IT here
    (read BASE_COLS from features.py and assert fd covers them).

B2. _vectorize(feature_dict: dict) -> pd.DataFrame  (1 row, model-ready)
        df = derive_features(feature_dict)             # -> 1-row DataFrame
        # impute any missing/NaN engineered col with training median
        for c in _COLS:
            if c not in df.columns:
                df[c] = _MEDIANS.get(c, 0.0)
        df = df[_COLS]                                 # exact order
        df = df.apply(pd.to_numeric, errors="coerce")
        df = df.fillna(pd.Series(_MEDIANS)).fillna(0.0)
        df = df.replace([np.inf, -np.inf], 0.0)
        return df

B3. predict(feature_dict: dict) -> float
        X = _vectorize(feature_dict)
        p = float(_MODEL.predict_proba(X)[0, 1])
        return min(1.0, max(0.0, p))                   # clamp defensively

    predict_many(list[dict]) -> list[float]            # loop or vstack; small N

B4. band(prob: float) -> str
        # decision bands for the UI (independent of scoring.py's health bands)
        if prob >= 0.80: return "critical"
        if prob >= _THRESH: return "at_risk"           # _THRESH ~0.5 or card val
        if prob >= 0.30: return "watch"
        return "healthy"

B5. explain(feature_dict, top_n=5) -> list[{feature, value, contribution}]
    Cheap per-prediction driver list for the UI / LLM.
    Preferred: SHAP if available
        import shap
        _EXPL = shap.TreeExplainer(_MODEL)             # build once at module load
        sv = _EXPL.shap_values(X)[0]
        pairs = sorted(zip(_COLS, X.iloc[0].tolist(), sv),
                       key=lambda t: abs(t[2]), reverse=True)[:top_n]
    Fallback (no shap): use _MODEL.feature_importances_ * (x - median) as a
    rough signed contribution. Mark method in the output.
    NOTE: this is the ML explanation; scoring.py's risk_breakdown is the
    rule-based one. The UI shows both — "two methods".

B6. predict_from_customer(customer_row) -> dict   (the orchestrator entry point)
        fd = build_feature_dict(customer_row)
        p  = predict(fd)
        return {
          "churn_probability": round(p, 4),
          "band": band(p),
          "threshold_used": _THRESH,
          "top_features": explain(fd, top_n=5),
          "model_version": _VERSION,
        }

B7. health() -> dict     (for Step 8 GET /ml/health)
        return {"loaded": True, "n_features": len(_COLS),
                "model_version": _VERSION, "threshold": _THRESH,
                "test_auc": _CARD.get("test_auc"),
                "test_pr_auc": _CARD.get("test_pr_auc")}

PART C — IMPORT PATH / PACKAGING GOTCHA
-------------------------------------------------------------------------------
app/services/ml_model.py does `from ml.features import derive_features`.
For that to resolve when running `uvicorn app.main:app` from the repo root:
  - repo root must be on sys.path (it is, when uvicorn is launched from root)
  - ml/ needs an __init__.py  -> add `ml/__init__.py` (empty) if missing
  - tests run from root too (pytest rootdir already = repo root, confirmed)
If you prefer isolation, alternatively COPY features.py logic into a shared
package `app/ml_features.py` imported by BOTH train and serve — but a single
file imported twice is simpler. Keep ml/features.py as the one copy.
