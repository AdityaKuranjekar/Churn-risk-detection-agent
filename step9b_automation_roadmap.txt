WHAT THIS IS (and is NOT)
-------------------------
IS:  a polished, presentation-grade panel that shows how the agent becomes a
     fully automated, event-driven Customer-Success system with n8n as the
     orchestration layer. It communicates "the production design is worked
     out; we are ready to build all of it."
IS NOT: a live n8n instance, a webhook, or any backend change. The current
     build's app/services/orchestrator.py already performs this exact
     sequence in-process — the roadmap panel says so, honestly, in Section 6.

FRAMING FOR JUDGES (put this sentence in the modal footer):
  "Everything in this blueprint runs today as an in-process Python pipeline
   (orchestrator.py). n8n adds scheduling, event triggers, retries,
   integrations (Slack / email / CRM), and a visual operations canvas —
   without moving business logic out of the backend."

PART B — SHARED DIAGRAM PRIMITIVES (build once, reuse in every tab)
-------------------------------------------------------------------------------
All diagrams are INLINE SVG. No libraries, no CDN. Use the design tokens.

B1. Palette (from PART B of step9_frontend.txt):
    node fill        #ffffff
    node stroke      var(--border-2) #d0d5dd, 1px
    node title text  var(--text) 12px 600
    node sub text    var(--text-3) 11px
    connector stroke var(--border-2), 1.5px
    arrowhead        var(--text-3)
    accent node      fill var(--accent-weak), stroke var(--accent)
    branch/decision  diamond, stroke var(--high) #dc6803
    "n8n" group box  dashed stroke var(--accent), fill var(--accent-weak) 40%

B2. <defs> arrowhead marker (put once per svg):
    <marker id="arw" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7"
      markerHeight="7" orient="auto-start-reverse">
      <path d="M0,0 L10,5 L0,10 z" fill="var(--text-3)"/>
    </marker>
    connectors: <path ... marker-end="url(#arw)"/>

B3. node(x,y,w,h,title,sub,variant) -> returns an SVG <g> string:
    rounded rect (rx=8) + title text + optional sub text (wrap at ~22 chars).
    variants: "default" | "accent" | "io" (dotted stroke).

B4. Flow animation (cosmetic): 2 small circles (r=2.5, fill var(--accent))
    travelling along each main connector via CSS:
      @keyframes flow { from{offset-distance:0%} to{offset-distance:100%} }
      .flow-dot{ offset-path: path("<same d as the connector>");
                 animation: flow 1.8s linear infinite; }
    Stagger the second dot with animation-delay:.9s.
    prefers-reduced-motion: reduce  -> hide .flow-dot entirely.

B5. On tab open: fade+slide nodes in with a ~120ms stagger (JS adds .in;
    CSS transitions transform/opacity). Reduced-motion -> show immediately.

B6. Responsive: diagrams are fixed-width SVG (e.g. viewBox 0 0 860 520) inside
    an overflow-x:auto div. Do NOT try to reflow the graph; horizontal scroll
    on small screens is fine and expected for an architecture diagram.

PART D — TAB 2: DAILY WORKFLOW  (scheduled, the headline n8n canvas)
-------------------------------------------------------------------------------
Single vertical chain of n8n nodes (this is what you'd literally show on the
n8n canvas in a live demo). Each node: title (600) + tiny "n8n node type"
sub in --text-3. Copy exactly:

  1  Schedule Trigger        sub: "Cron · every day 06:00"
  2  Fetch usage             sub: "HTTP Request → /internal/usage"
  3  Fetch support tickets   sub: "HTTP Request → /internal/support"
  4  Fetch latest feedback   sub: "HTTP Request → /internal/feedback"
  5  Aggregate signals       sub: "Function · 30/90-day windows"
  6  Health score            sub: "HTTP → /risk/breakdown (rule engine)"
  7  Churn probability       sub: "HTTP → /ml/predict (XGBoost)"
  8  IF  risk gate           sub: "churn ≥ 0.50 OR band ∈ at-risk/critical"
       ├── FALSE → [Log: monitor]              (short branch, --text-3)
       └── TRUE  ↓
  9  LLM · analyze why       sub: "AI node · grounded in signals"
  10 Retrieve playbook (RAG) sub: "Vector search · top-1 of 10 playbooks"
  11 LLM · next-best-action  sub: "AI node · action constrained by rules"
  12 Generate CSM message    sub: "AI node · personalized draft"
  13 Store recommendation    sub: "HTTP → /analyses (Postgres)"
  14 Notify CSM              sub: "Slack / Email · with Approve link"

Render node 8 as a diamond; nodes 9-12 grouped with a faint "AI" band label.
Caption: "Same steps as orchestrator.analyze_customer() today — n8n adds the
schedule, the fan-in fetches, retries, and the CSM notification."

PART E — TAB 3: EVENT-DRIVEN  (reactive automation)
-------------------------------------------------------------------------------
Short vertical flow, exact copy:

  [Webhook Trigger]   sub: "Customer feedback / NPS submitted"
      ↓
  [Sentiment analysis]  sub: "AI node"
      ↓
  <IF sentiment negative?>   (diamond)
      ├── NO  → [End · store only]
      └── YES ↓
  [Look up account risk]  sub: "HTTP → /customers/{id}"
      ↓
  <IF churn ≥ 0.70?>   (diamond)
      ├── NO  → [Queue for daily run]
      └── YES ↓
  [Escalate to CSM]  sub: "Slack DM · P0"
      ↓
  [Draft recommended response]  sub: "AI node"

Caption: "The nightly batch catches slow decline. Event triggers catch the
sudden 'your update broke my reports' moment — the system reacts in seconds,
not hours."

PART G — TAB 5: WHO DOES WHAT  (responsibility split table)
-------------------------------------------------------------------------------
Simple 2-col table, hairline rows, --fs-13:

  React        User experience
  FastAPI      Application APIs, business rules, persistence, auth
  PostgreSQL   Source of truth (+ pgvector for playbook embeddings)
  XGBoost      Churn probability & feature attribution (SHAP)
  n8n          Orchestration, schedules, event triggers, AI workflow,
               external integrations, retries, observability
  LLM (Gemini) Reasoning, root-cause explanation, message personalization

Caption: "n8n for triggers → orchestration → AI steps → integrations →
actions. Backend for data → APIs → rules → persistence → auth. Keeping the
line clear is what makes the architecture mature — not pushing everything
into workflow nodes."

Also list, as a short "n8n anti-patterns we avoid" note (--text-3):
  "Not doing: health-score math across 15 nodes · React calling n8n for every
   click · 10 LLM calls where 2 suffice."
